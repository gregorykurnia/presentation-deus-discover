# DEUS Pitch Deck Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the DEUS Game-Based Assessment pitch deck in the "Daybreak, refined" design as an HTML deck that approved Google accounts can edit (text, pictures, slide order), lock and publish, while everyone else only sees a read-only version or the PDF.

**Architecture:** All slide content lives in one JSON document (text, image references, notes, order). One renderer turns that JSON into 1920×1080 slides using a small set of layout templates. Three things read the same JSON: the **presenter** (read-only), the **editor** (signed-in, allowlisted Google accounts only), and the **PDF/offline exporters**. Firebase holds the draft, the published versions and the uploaded images, and its security rules (not the UI) enforce who can edit and when the deck is locked.

**Tech Stack:** Vanilla JS (ES modules) + Vite, Vitest (unit), Playwright (PDF export, e2e, QA screenshots), Firebase (Google sign-in, Firestore, Storage, Hosting), `@firebase/rules-unit-testing` + Firebase emulators, DM Sans variable font via `@fontsource-variable/dm-sans` (opsz axis, bundled, offline).

**Spec:** `deck-brief.md` (content, slide purposes, technical requirements) + this document's "How it works for you" section (editing/locking requirements) + design reference `design-options/design-options-v2.html`, option 1 "Daybreak, refined".

## How it works for you (plain-language summary)

| You want to… | How |
|---|---|
| **Edit text** | Open `…/edit`, sign in with Google. Click any text on a slide and type. It autosaves. If text gets too long for its box, the box turns red; it is never silently shrunk. |
| **Change a picture** | Click (or drag a file onto) any picture box → choose a file. Set "fill / fit" and drag a focus point so faces don't get cropped. |
| **Reorder slides** | Drag thumbnails in the left sidebar. You can also hide, duplicate or delete a slide. Hidden slides are skipped in the presenter and the PDF. |
| **Control who can edit** | An allowlist of Google emails (you are the owner). Only those accounts can save. Everyone else is rejected by the server, even if they find the edit link. |
| **Lock it** | The owner presses **Lock**. Nobody (including other editors) can change the draft until the owner unlocks it. |
| **Present / send it** | Press **Publish**. This freezes a numbered version (v1, v2…). The share link always shows the latest *published* version, read-only, with no editing code in it. Your unfinished draft edits are never visible to clients. |
| **Get a PDF** | `npm run pdf` exports the published version to `DEUS-Pitch.pdf` (one slide per page, backgrounds printed, video slide shows the poster + link + QR). |
| **Present offline** | `npm run export:offline` produces `deck.html`, plus a `dist/offline/` folder that runs from a USB stick with no internet. |

> Sanity check: Google Slides would give editing/permissions/PDF for free but not this design or the HTML requirements in the brief. This plan keeps the custom design and adds only the editing you asked for.

## Global Constraints

- Slides are 1920×1080; the browser scales to fit and keeps the aspect ratio. Arrow keys / space navigate, **N** toggles notes, **F** toggles fullscreen.
- Use deck-brief.md text **exactly**. No added claims, numbers, features or bullets. Every `[bracketed placeholder]` stays as is. Bahasa Indonesia quotes are verbatim.
- `[placeholders]` are highlighted; `SHOW_PLACEHOLDER_HIGHLIGHT` is the first line of the presenter script and turns highlighting off.
- Speaker notes per slide are stored in a `data-notes` attribute on each rendered slide.
- A missing image file renders a clean labeled box describing what goes there.
- Text never auto-shrinks to fit. Overflow is reported (editor warning + QA failure).
- Minimum on-slide text size is 26px at 1920 width (readable across a room). Headlines are 60px or larger.
- Fonts are bundled in `assets/fonts/`, with no network needed for presenting or PDF.
- Design tokens come from Daybreak, refined: ink `#0F1A3A`, muted `#4B5677`, cobalt `#2D5BFF`, coral `#FF6F4E`, sky `#D3E2FF`, peach `#FFDCCB`, lilac `#ECE4FF`, font DM Sans. Discs are about 15% more saturated than the mockup so they survive projectors.
- Borrowed from the other options: a small "DEUS logo · slide number" header on content slides, and a full-height photo on the proof slide.
- No Agaté / Level Up / "Next Chapter" branding anywhere. The Personality module is "Heroes of a Fallen Land" (see `assets/SOURCES.md`).
- No stock photos. Only files in `assets/` or user uploads.

## Review Focus

1. **Text edited too long for its box.** Expected: red outline + "Text doesn't fit" in the editor, the QA script fails listing the slide; never a smaller font. (Test in Task 7 + Task 6.)
2. **Awkward image uploads** (20 MB phone photo, HEIC, portrait photo in a landscape slot). Expected: >10 MB or a non-JPEG/PNG/WebP is rejected with a clear message; portrait images fill with the chosen focus point. (Test in Task 8.)
3. **Hidden or reordered slides.** Expected: presenter, slide numbers, `placeholders.md` and the PDF all follow the current order and skip hidden slides; the appendix keeps A1… numbering. (Tests in Task 1 + Task 6.)
4. **Two editors saving at once.** Expected: the second save is rejected with "Someone else changed this deck. Reload to see their changes", never a silent overwrite. (Test in Task 10.)
5. **A viewer, or a signed-in non-allowlisted person, opening `/edit`, or anyone editing while locked.** Expected: read-only UI, and the server rejects writes regardless of UI. (Rules tests in Task 10.)

```

src/config.js                # SHOW_PLACEHOLDER_HIGHLIGHT and constants

src/layouts/*.js             # one file per layout template (13)
src/styles/daybreak.css      # tokens, type scale, slide frame, print CSS
src/present/present.js       # presenter: scaling, keys, notes, fullscreen
src/editor/*.js              # editor UI: text, images, sorter, notes, toolbar
src/store/local.js           # store adapter: localStorage + JSON file
src/store/firebase.js        # store adapter: Firestore/Storage/Auth
present.html, edit.html      # entry points (edit bundle never loaded by present)
scripts/build-offline.js     # writes self-contained deck.html (repo root) + dist/offline/
export-pdf.js                # Playwright -> DEUS-Pitch.pdf (repo root, name fixed by the brief)
deck.html                    # build output at repo root, name fixed by the brief
scripts/qa.js                # per-page screenshots + overflow check
scripts/placeholders.js      # writes placeholders.md
firestore.rules, storage.rules, firebase.json
tests/unit/*.test.js, tests/e2e/*.spec.js, tests/rules/*.test.js
```

**Deck JSON shape** (the contract everything shares):

```json
{
  "id": "deus-pitch",
  "rev": 12,
  "slides": [
    {
      "id": "s-title", "layout": "title", "section": "main", "hidden": false,
      "fields": { "headline": "Fit the role, they perform. Fit your company, they stay.", "...": "..." },
      "images": { "clientLogo": { "src": null, "fit": "contain", "focus": [50, 50], "label": "Client logo" } },
      "notes": "Open with: …"
    }
  ]
}
```

`section` is `"main"` or `"appendix"`. `rev` increments on every save (used for conflict detection).
